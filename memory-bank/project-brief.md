# Project Brief

마지막 갱신: 2026-07-29
상태: 첫 버전 완료 및 사용성 확인 중

## 한 줄 설명

지정한 아파트의 실거래가를 동·구조·층별로 비교해 현재 매물 가격이 시세에 비해 적정한지 판단하도록 돕는 부동산 분석 프로젝트다.

## 해결하려는 문제

아파트 가격은 시간에 따라 변하므로 과거 실거래가를 단순 나열하는 것만으로는 현재 매물의 적정 가격을 판단하기 어렵다.

특정 기간의 실거래를 같은 아파트 안에서 동·구조·층 조건별로 비교하고 가격 차이를 비율로 표현해, 검토 중인 매물이 유사 조건의 시세보다 저렴한지 적정한지 비싼지 판단할 수 있어야 한다.

## 주요 사용자

우선 사용자는 본인이 매수할 아파트를 알아보는 개인이다. 향후 다른 분석 사용자는 별도로 인터뷰해 확장한다.

## 핵심 사용 시나리오

1. 사용자가 분석할 아파트를 지정한다.
2. 해당 아파트의 입주 이후 확보 가능한 전체 실거래가를 가져온다.
3. 거래를 아파트 동, 동일 전용면적 내 평면 타입과 층 조건으로 구분한다.
4. 조건별 가격과 가격 차이를 금액 및 백분율로 비교한다.
5. 사용자가 검토 중인 매물 가격을 입력한다.
6. 유사 조건의 실거래 시세와 비교해 상대적으로 저렴한지, 적정한지 또는 비싼지 판단할 근거를 보여준다.

## 첫 번째 버전 범위

- Python Streamlit으로 실행하는 로컬 웹 대시보드
- `동탄시범한빛마을한화꿈에그린` 단일 단지 지원
- 인터넷 또는 API를 통한 지정 아파트의 실거래가 자동 수집
- 입주 이후 확보 가능한 전체 기간의 거래 이력 구성
- 아파트 동·동일 전용면적 내 평면 타입(A/B/C 등)·층별 거래 분류
- 각 거래의 실제 층 표시와 저층·중층·고층 구간별 가격 요약
- 조건별 가격 수준과 가격 차이의 백분율 계산
- 전체 기간의 모든 실거래를 계약일·가격·평면 타입별 점으로 표시
- 연도별 평면 타입 거래 건수 표시
- 층 구간별 A/B/C 타입 평균가격 막대와 개별 실거래가격 분포 표시
- 현재 선택 기간에서 같은 타입의 고층 평균을 100%로 둔 층 구간별 가격 비율 표시
- 검토 중인 매물 가격과 유사 조건 실거래 비교
- 비교 결과와 주요 근거 표시

## 범위 밖

- 첫 버전에서 여러 아파트를 한꺼번에 비교하는 기능
- 전국 아파트 검색과 자동 단지 등록
- 투자 수익률, 대출과 세금 분석
- 미래 가격 예측
- 첫 기능과 직접 관련 없는 부동산 분석

## 성공 기준

- 사용자가 지정한 아파트와 기간에 해당하는 실거래를 확인할 수 있다.
- 동일 아파트와 전용면적 내에서 동·평면 타입·층 조건에 따른 가격 차이를 금액과 백분율로 확인할 수 있다.
- 개별 거래의 실제 층과 층 구간별 표본 수 및 대표 가격을 함께 확인할 수 있다.
- 입주 이후 전체 기간에서 타입별 가격 차이와 거래량의 변화 추세를 확인할 수 있다.
- 검토 중인 매물 가격이 비교 거래 대비 어느 수준인지 근거와 함께 확인할 수 있다.
- 구체적인 정확도와 사용성 기준은 데이터 출처와 비교 방법을 확정한 뒤 추가한다.

## 데이터와 출처

- 필요한 데이터: 아파트 식별 정보, 계약일, 거래가격, 전용면적, 평면 타입(A/B/C 등), 층, 동 정보
- 검토 매물 데이터: 매물 가격, 동, 전용면적, 평면 타입, 층
- 사용자는 첫 대상 단지에서 A 타입을 선호하지만 현재 검토 중인 특정 매물은 없다.
- 사용자는 보유 자료가 없으므로 첫 버전부터 인터넷 또는 API를 통해 데이터를 자동 수집해야 한다.
- 사용자는 공공데이터포털 회원가입과 국토교통부 실거래가 API 활용신청을 완료했다.
- 실거래 후보 출처: 국토교통부의 아파트 매매 실거래가 상세 Open API
- 단지·동 식별 후보 출처: 한국부동산원의 공동주택 단지 식별정보 Open API
- 국토교통부 API는 층을 제공하고 소유권 이전등기가 완료된 거래에 한해 동을 추가 공개하므로, 거래별 동 정보가 항상 존재하지 않을 수 있다.
- 호갱노노 등 민간 서비스는 국토교통부 실거래에 자체 단지·평면 정보를 결합해 거래별 A/B/C 타입을 표시하는 것으로 보인다.
- 호갱노노에서 첫 대상 단지의 거래가 `109A`, `109B`, `109C` 등으로 구분되어 표시되는 것을 확인했다.
- 민간 서비스 화면에 정보가 공개되어 있어도 공식 API 제공 여부, 자동 수집 허용 범위와 데이터 사용 조건은 별도로 확인해야 한다.
- 첫 버전은 로컬에서 수동 새로고침하며, 취소 거래는 제외하고 동 누락 거래는 미공개로 표시한다.

## 제약과 가정

- 빠른 결과와 반복 경험을 우선하는 초보자용 바이브 코딩 프로젝트다.
- 기능은 작은 단위로 만들고 직접 사용해 본 뒤 확장한다.
- 첫 결과물은 Python Streamlit 기반 로컬 웹 대시보드로 만든다.
- 첫 버전은 `동탄시범한빛마을한화꿈에그린` 전용으로 구현한다.
- 이후 사용자가 요청하는 한빛마을 아파트를 하나씩 추가할 수 있도록 단지별 식별정보와 타입 매핑은 코드 로직과 분리한다.
- 전국 아파트 검색은 실제 필요성이 확인되기 전까지 구현하지 않는다.
- `구조`는 서로 다른 평수가 아니라 동일 전용면적 안의 A/B/C 등 평면 타입을 뜻한다.
- 평면 타입별 선호도 차이가 실거래 가격 차이로 나타날 수 있다는 가설을 검증한다.
- 시간에 따른 시장 전체의 가격 변동과 동·구조·층에 따른 가격 차이를 구분할 비교 방법이 필요하다.
- 거래량이 적은 조건에서는 단순 평균과 백분율이 왜곡될 수 있으므로 표본 수와 거래 시점을 함께 표시해야 한다.
- 기본 분석 기간은 단지 입주 시점인 2007년부터 확보 가능한 최신 거래까지의 전체 기간이다.
- 타입별 가격 차이는 전체 실거래 점의 위치와 분포로 확인한다.
- 연도별 거래 건수는 거래 활발도의 참고 지표이며 선호도를 직접 측정한 값으로 해석하지 않는다.
- 거래 원본에는 실제 층을 유지하고 통계 요약은 1층·저층(2~5층)·중층(6~15층)·고층(16층 이상)으로 묶는다.
- 층 구간은 동 정보 공개 여부와 무관하게 실제 층만으로 분류한다.
- 첫 분석 대상은 경기도 화성시 동탄구 반송동 21, 동탄시범한빛길 10의 `동탄시범한빛마을한화꿈에그린`이다.
- 이 단지는 534세대, 6개 동, 2007년 3월 사용승인 단지이며 사용자가 매수를 희망하는 첫 번째 핵심 분석 대상이다.
- 이름이 비슷한 `동탄나루마을한화꿈에그린` 및 `동탄나루마을한화꿈에그린우림필유`와 구분한다.
- 나머지 제약과 가정은 인터뷰에서 확정한다.
